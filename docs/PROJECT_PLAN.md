# PROJECT_PLAN — 高等学校 体育学習Webプラットフォーム

## 1. プロジェクト概要

高等学校「保健体育（科目：体育）」の学習指導要領に示される全8領域を網羅し、生徒が
**学ぶ（コンテンツ閲覧）→ 記録する（データ入力）→ 振り返る（グラフで推移確認）** を
1つのWebサイトで完結できる学習プラットフォームを構築する。

| 項目 | 内容 |
|---|---|
| 対象 | 高校生（1〜3年）および体育科教員 |
| 利用端末 | Chromebook / iPad / PC（スマートフォンでも崩れないこと） |
| ホスティング | GitHub Pages（完全静的サイト：HTML / CSS / JavaScript のみ） |
| データ保存先 | 生徒個人の Google スプレッドシート |
| API | Google Apps Script（GAS）の Web アプリ |
| グラフ | Chart.js（CDN読み込み、バージョン固定） |
| ビルド工程 | なし（素のHTML/CSS/JSのみ。npm等に依存しない） |

## 2. 対象領域（学習指導要領 A〜H）

| 記号 | 領域 | 主な内容 | 記録・グラフ化の例 |
|---|---|---|---|
| A | 体つくり運動 | 体ほぐしの運動 / 実生活に生かす運動の計画 | 体力テスト各種目、運動計画の実施記録 |
| B | 器械運動 | マット運動 / 鉄棒運動 / 平均台運動 / 跳び箱運動 | 技の習得状況（できた技の数・自己評価） |
| C | 陸上競技 | 短距離走・リレー / 長距離走 / ハードル走 / 跳躍 / 投てき | タイム、距離、高さの推移 |
| D | 水泳 | クロール / 平泳ぎ / 背泳ぎ / バタフライ / 複数の泳法・リレー | 泳法別タイム・距離 |
| E | 球技 | ゴール型 / ネット型 / ベースボール型 | 個人スタッツ、ゲーム振り返り |
| F | 武道 | 柔道 / 剣道 など | 技の習得状況、自己評価 |
| G | ダンス | 創作ダンス / フォークダンス / 現代的なリズムのダンス | 自己評価・相互評価の推移 |
| H | 体育理論 | スポーツの文化的特性 / 効果的な学習の仕方 / 豊かなスポーツライフの設計 | 確認テストの得点推移 |

## 3. システム構成

```
[生徒のブラウザ]
   │  GitHub Pages から静的ファイルを取得
   │  （index.html / css / js / pages）
   │
   │  fetch()  GET: 読み込み / POST(text/plain): 書き込み
   ▼
[GAS Webアプリ]  ←― 生徒ごとに自分のスプレッドシートへバインド・デプロイ
   │
   ▼
[生徒個人の Google スプレッドシート]  (Records / Profile シート)
```

### 3.1 認証・接続方式（初期案）

1. 教員がテンプレートのスプレッドシート（GASバインド済み）を用意する。
2. 生徒は自分の Google アカウントでテンプレートを「コピー」する。
3. 生徒はコピーしたシートの GAS を「ウェブアプリ」としてデプロイする
   （実行ユーザー：自分 / アクセス：全員）。
4. 生徒は発行された Web アプリURLと、自分で決めた**合言葉（トークン）**をサイトの「設定」画面に入力する。
   入力値はブラウザの localStorage に保存される。
5. 以降の通信には毎回トークンを付与し、GAS 側はスクリプトプロパティに保存されたトークンと照合する。

> **補足（CORS）**: GAS の Web アプリは独自のレスポンスヘッダーを設定できない。
> そのため、POST は `Content-Type: text/plain` で送信してプリフライト（OPTIONS）を発生させない
> 「シンプルリクエスト」とする。GAS の応答は `script.googleusercontent.com` へリダイレクトされ、
> そこで `Access-Control-Allow-Origin: *` が付与されるため、ブラウザから JSON を読み取れる。

> **検討事項**: 学校の Google Workspace 管理設定によっては「アクセス：全員」でのデプロイが
> 禁止されている場合がある。その場合は「ドメイン内のユーザー」での運用可否を検証する（ROADMAP Phase 1）。

## 4. エージェント（役割）定義

本プロジェクトは PM が全体を統括し、以下の専門エージェントの役割を切り替えながら進行する。

### 4.1 PMエージェント（統括）
- 要件定義・スコープ管理・優先順位付け
- `docs/ROADMAP.md` / `docs/TODO.md` の更新と進捗管理
- 各エージェントへのタスク割り当てと成果物のレビュー
- ユーザー（発注者）への報告・承認依頼

### 4.2 Frontendエージェント
- HTML / CSS / JavaScript（ES Modules、フレームワーク不使用）による画面実装
- レスポンシブデザイン（Chromebook / iPad / PC、横向き・縦向き両対応）
- アニメーション・図解などの視覚表現（CSSアニメーション / SVG）
- アクセシビリティ（コントラスト、キーボード操作、タップ領域 44px 以上）

### 4.3 Data/APIエージェント
- `gas_backend.gs`（GAS 側API）の設計・実装
- `js/api.js`（フロント側通信モジュール）の実装
- Chart.js を用いたグラフ化（`js/charts.js`）
- スプレッドシートのシート設計・データ形式の定義、エラーハンドリング

### 4.4 PE Contentエージェント
- 学習指導要領（平成30年告示・高等学校）に基づく A〜H 各領域のコンテンツ設計
- 学習のねらい、技能のポイント、ルール・用語解説のテキスト作成
- ルール図解・動きの図解の構成案（Frontend へ渡す仕様）
- 記録項目（測定種目・単位・評価観点）の定義

## 6. 非機能要件・制約

- 個人情報は生徒自身のスプレッドシートにのみ保存し、サイト側（GitHub）には一切保存しない。
- 外部ライブラリは CDN からバージョン固定で読み込む（例：Chart.js 4.4.1）。
- 学校ネットワーク・低速回線を想定し、画像は WebP / SVG を優先し軽量化する。
- 対応ブラウザ：最新の Chrome（Chromebook 含む）/ Safari（iPadOS）/ Edge。
